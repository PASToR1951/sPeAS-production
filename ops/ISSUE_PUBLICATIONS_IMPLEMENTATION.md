## Model and workflow

Existing `compiled_documents`, `documents` and `compiled_document_items` retain their IDs and relationships. No duplicate journal catalog is introduced. Migration `0016_issue_renditions.sql` adds immutable complete-issue renditions with a catalog fingerprint, PDF hash, page count, manifest and explicit review. Old records are not automatically split, backfilled or published.

Migration `0017_issue_revisions.sql` adds private correction revisions and retained abstract-extraction diagnostics. A correction clones the current reviewed layout into a private workspace while the previous publication remains available. Administrators prepare and review its papers and complete PDF, then publish the replacement in one transaction. Existing paper and issue IDs remain stable; original sources, prior renditions and publication history remain retained. Concurrent or stale corrections cannot overwrite a newer publication.

The feature-gated import workspace offers complete-issue and separate-paper arrangements. Complete-issue uploads stage the main PDF and cover assets without inferring paper count. Administrators identify inclusive physical ranges and account for front matter, embedded covers or excluded sections. Unaccounted pages, overlaps, reversed ranges and bounds violations block commit. Existing fixed-PDF range controls and the per-paper preparation worker extract standalone papers and their abstracts. Foreword review stays separate. Journal papers use their journal document type, not a thesis label. Synergy's issue number can be absent.

Separate-paper imports retain conversion and multipart stitching. Cover/front-matter sources can be staged without becoming papers. Collection details control publication order. The existing guided compiled wizard also supports complete-issue assembly after its private records are saved; the catalog preview offers the same preparation/review panel.

Collection drafts can be saved before review. Sources and paper metadata remain in the existing recoverable workspace. Preparation/review failures never publish or silently replace a paper download with an issue file. Repeated paper commits and complete-issue assembly reuse their existing identities. Starting a different workspace uses a fresh idempotency key.

Commit saves papers privately. Complete-issue preparation then creates the immutable full PDF from the main source (preserving front matter) or from cover, foreword and ordered standalone PDFs. Embedded covers are not inserted twice. The manifest records source, standalone and complete-issue physical page mappings; printed page labels are separately represented and remain unknown until supplied editorially. Paper ranges are not printed pagination.

The complete issue must be previewed and explicitly reviewed before the preparation workspace or managed guided-upload publication gate approves it. Reader requests serve stored outputs; they never perform assembly. Catalog/source changes invalidate the complete output fingerprint. A held/withdrawn paper makes its containing issue private. Saving a publication hold in either review system also withdraws the affected public records through database triggers. Clearing a hold does not republish them.

Public issue pages provide distinct complete-issue read/download actions and per-paper read/download actions. Long titles wrap, controls stack on narrow screens, and longer contents lists support title/author filtering. Paper pages link back to their issue. Public search and suggestions can find included papers directly, and search displays separate paper/issue counts and result types. Public asset endpoints accept record references, including existing UUIDs, and resolve authorized assets on the server.

## Limits and activation

- Apply migrations through `0017` before activating the rebuilt application.
- Enable `IMPORT_PREPARATION_ENABLED=true` for the extended import workspace and run the existing import worker. `VOLUME_READER_ENABLED=true` enables the optional existing contents reader. The distinct complete PDF endpoints and paper detail reader do not require that reader flag.
- Each preparation group permits 20 included files and 100 MB combined, with a 100 MB prepared-output limit. A batch workspace permits 500 staged files and 1 GB total. These reuse existing deployment limits; the implementation adds no larger issue-output ceiling.
- Complete-issue range selection uses a fixed PDF. Word components convert to fixed PDFs before ranges are selected. An administrator can explicitly select authoritative replacement components for a paper and retain its original main-issue range. Assembly substitutes the reviewed standalone PDF for that range, recalculates all following page mappings and excludes the original paper pages. Silently mixed sources are rejected.
- No production database, public records, services or feature settings were changed during this implementation.
